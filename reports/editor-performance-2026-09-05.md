# Проверка текста: задержки и переносы строк

Изменения подготовлены локально 05.09.2026. Продакшен не обновлялся.
Проверенный серверный коммит: `d1c50ffdd09ebd0c94d1b499fa0f49b6a2ab7b4f`,
`spell-checker.service` — `active`.

## Причины

1. Один таймер на 3 секунды применялся и к набору, и к вставке/Enter.
   При наборе такая задержка нужна, чтобы пользователь успел дописать слово.
2. `add_word` и `WordToSpan` разбирали HTML регулярными выражениями и заново
   записывали `innerHTML`. Переносы, пустые блоки и позиция курсора зависели от
   преобразований `<div>`, `<br>` и пробелов; обновление затрагивало весь текст.
3. Сервер немедленно вызывал `suggest()` для каждого неизвестного слова.
   Проверка `spell()` гораздо дешевле подбора вариантов.
4. Браузер запускал все пакеты одновременно и не отличал ожидающие ответа слова
   от ещё не отправленных; при последующих изменениях запросы могли повторяться.
5. Синхронные Hunspell и SQLite выполнялись внутри `async def` обработчика.

## Замеры

На действующем сервере для слов `уйнған`, `эшлгән`, `тороуо`:

| Операция | Время на слово |
|---|---:|
| `spell()` | 0,17–0,21 мс |
| `suggest()` | 115,48–131,77 мс |

Существующий локальный HTTP API сервера обработал 7 слов (4 правильных и 3
ошибочных) за 383 мс. Замер был коротким, без нагрузочного теста.

Локально с настоящим Python Hunspell и тем же словарём, с очисткой кешей перед
каждым измерением, `spellChecker()` для тех же 7 слов:

| Режим | Время вычисления |
|---|---:|
| Проверка и все варианты | 367,392 мс |
| Проверка без вариантов, первый замер | 1,084 мс |
| Проверка без вариантов, второй замер | 0,960 мс |

Это замеры вычисления на небольшой выборке, без браузера и сети; они не означают
такого же ускорения полной загрузки любого текста.

## Реализация

- Набор букв сохраняет задержку **3000 мс**. Вставка, пробел, пунктуация и Enter
  запускают проверку сразу. Ввод через IME проверяется после завершения композиции.
- Подсветка использует DOM Range и CSS Highlight. Текст редактора, переносы,
  выделение и история Undo при проверке не изменяются. Для браузеров без Highlight
  есть отдельный слой подчёркиваний вне редактируемого текста.
- Вставка принимает только текст; `<img>` и другой HTML остаются текстом.
  Отдельный обход DOM для копирования/счётчиков исключает служебные `<br>` браузера.
- Новый запрос `/data_processing` с `include_suggestions: false` возвращает
  `word`, `correct`, `variants: []`. Ошибка определяется полем `correct`, в том
  числе когда словарь не нашёл ни одного варианта.
- `/suggestions` принимает `{"word": "..."}` и вызывается при открытии исправлений.
  Меню расположено вне редактора и не попадает в проверяемый/копируемый текст.
- Браузер отправляет последовательно пакеты до 100 уникальных слов; повторные
  слова берутся из кеша. Ответы от старого текста не изменяют новый текст.
- На сервере кешируются до 20 000 результатов проверки и 2 000 наборов вариантов.
  Доступ к одному Hunspell защищён блокировкой. Обычные `def` обработчики
  исполняются FastAPI в рабочем пуле. Это не даёт отдельного ядра каждому запросу:
  единственный экземпляр Hunspell и GIL остаются ограничениями при высокой нагрузке.
- Старый контракт API (без параметра `include_suggestions`) сохранён. Его запись
  статистики и запись после запроса вариантов перенесены в BackgroundTasks.
  **Быстрая проверка не записывает строки в `text.db`**: число вариантов неизвестно;
  нельзя затирать существующие значения нулями. При необходимости полной статистики
  всех проверенных слов потребуется отдельно определить её схему и сбор.
- При отсутствии Hunspell возвращается 503 вместо фиктивной успешной проверки.
  Браузер показывает ошибку и кнопку повторной попытки.
- Удалены четыре неиспользуемых внешних JS-библиотеки; Bootstrap CSS сохранён.

Справочная документация: [CSS Custom Highlight API](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Custom_Highlight_API),
[FastAPI: обычные и асинхронные обработчики](https://fastapi.tiangolo.com/async/).

Запуск браузерных тестов из корня проекта:

```sh
python3 -m http.server 8766 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8766/tests/editor.html` и
`http://127.0.0.1:8766/tests/editor.html?fallback`. Это отдельная страница с
имитацией ответов API, не публикуемая FastAPI-приложением. API-тестам нужны
FastAPI и httpx; на сервере для них использовать Python из `venv`.

Для публикации потребуются коммит, push и деплой по `AGENTS.md`, затем проверка
обычного API, быстрого режима, `/suggestions` и редактора на публичном сайте.
