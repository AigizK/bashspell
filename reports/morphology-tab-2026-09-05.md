# Морфологический разбор на сайте — 5 сентября 2026

Добавлена вкладка «Һүҙ составы» в стиле существующей проверки текста. Пользователь
вводит одно слово и получает все различные разборы, найденные в активном словаре:
словарную основу, часть речи, последовательность частей слова, грамматические
метки и их объяснения на башкирском языке. Легенда содержит только встреченные
в результате метки. Переключение вкладок сохраняет текст и переносы строк редактора.

Примеры разбора с частью речи `Noun`:

| Слово | Части | Метки |
| --- | --- | --- |
| халыҡтарҙыңмы | халыҡ + тар + ҙың + мы | Pl + Gen + Q |
| халыҡтарҙыңдыр | халыҡ + тар + ҙың + дыр | Pl + Gen + Indf |
| китапханаларыбыҙҙағыларҙың | китапхана + лар + ыбыҙ + ҙағы + лар + ҙың | Pl + PxPl1 + Der/дағы + Pl + Gen |

Для первых двух слов также показываются словарные альтернативы с частью речи
`A` и основой `халыҡтар`. Одинаковые основа, часть речи и последовательность меток
объединяются, даже если получены несколькими техническими путями.

## Почему отдельный анализатор

[Документация Hunspell](https://raw.githubusercontent.com/hunspell/hunspell/master/man/hunspell.5)
описывает ограничение обычного режима двумя последовательными суффиксальными
стадиями. Одна стадия может содержать несколько морфем, поэтому число меток
и число применений правила не совпадают. Причина и генерация составных правил
также описаны в [аудите грамматики](grammar-audit-2026-09-05.md).

`bashspell_morphology.py` читает те же `bash.aff` и `bash.dic`, что использует
проверка орфографии. Он ищет путь от полного слова к словарной основе, проверяя
флаги продолжения, условие каждого правила и точное восстановление слова.
Фиксированного предела в две стадии нет. Например, для
`китапханаланмағандарҙыңмы` найден путь из трёх стадий, который стандартный
`hunspell -m` с этим словарём не возвращает.

Окончания индексируются по добавляемой строке. Промежуточные состояния поиска
запоминаются в пределах запроса, результаты последних 256 слов кешируются.
Словарь загружается при первом запросе к `/analyze`, отдельно от объекта Hunspell.
Обработчик работает в пуле потоков FastAPI. Изменения словаря требуют перезапуска
приложения, чтобы оба анализатора загрузили новую версию.

## Точность и пределы

- «Нигеҙе» означает основу из словаря, а не гарантированный этимологический корень.
- Полный разбор требует существующей основы и разрешённой цепочки правил.
  Если полного пути нет, сайт сообщает, что анализ не найден; частичный разбор
  и предположительные окончания не выдаются.
- Составное добавление делится на отдельные части только там, где граница
  подтверждается другими правилами того же класса. При неоднозначной границе
  часть остаётся общей с несколькими метками. Все её грамматические метки
  сохраняются, а конкатенация частей всегда восстанавливает всё введённое слово.
- Чередования учитываются по применённому правилу: `китап + ы → китаб + ы`,
  `һүн + мә + ҫ + лек + е → һүн + мә + ҫ + лег + е`. Изменение звука
  объясняется рядом с разбором.
- Разбор ограничен 256 символами входа, 30 000 состояниями поиска и 5 000
  различными вариантами на состояние. Превышение бюджета завершает запрос
  ошибкой, а не выдачей неполного набора вариантов.
- Поддерживается формат текущего словаря: числовые флаги, суффиксальные правила
  и имеющийся класс префиксов изменения регистра. Неподдерживаемые новые
  директивы приводят к явной ошибке загрузки.
- Семантика разборов зависит от качества исходного словаря и правил.
  Легенда описывает их фактические обозначения; например, `Px…` применяется
  и к притяжательным формам имён, и к личным показателям глаголов.

Для терминологии использованы башкирские названия из
[статьи о системе форм глагола](https://uchbash.com/articles/bash-ort-tele-m-bi-te/2019-01-24/bash-ort-telend-ylym-formalary-sistema-y-morfologik-k-te-208689)
и [учебного материала по грамматике](https://kitaptar.bashkort.org/storage/books/0CjC8NFRA5LYUFo5767IPsZX8CfXcx7WnjU8YWIT.pdf).

## API

`POST /analyze`, JSON: `{"word": "халыҡтарҙыңмы"}`.

Ответ содержит `word`, массив `analyses` и `legend`. В каждом разборе:
`stem`, `pos`, `tags`, `parts`, `changes`, `steps`. `steps` содержит промежуточные
формы и номера строк правил в активном `bash.aff` для диагностики.

- `200`, пустые `analyses` и `legend`: полного разбора нет.
- `422`: пустой ввод, несколько слов, неподходящие символы или слишком длинное слово.
- `503`: поиск не завершён из-за ограничения объёма работы.

Интерфейс обрабатывает сетевые ошибки и позволяет повторить запрос. Старые
ответы не перезаписывают результат после изменения слова или нового запроса.

## Проверки

Выполнены локально:

```sh
python3 tools/complete_hunspell_paradigms.py --check
./bashspell --dict 28.01.2024 validate
python3 -m unittest discover -s tests -v
node --check static/js/morphology.js
git diff --check
```

Все 40 Python-тестов прошли. Новые тесты включают обязательные примеры,
неоднозначные разборы, чередования, API, отказ от частичных ответов, полный
охват меток легендой и синтетическую цепочку из 40 последовательных аффиксов.
Также проверены все 950 примеров из существующих грамматических наборов:
730 положительных форм разобраны, 220 отрицательных отклонены.

В браузере прошли 8 тестов нового интерфейса (`tests/morphology.html`)
и по 15 регрессионных тестов редактора (`tests/editor.html`) в режимах
CSS Highlights и `?fallback`. Проверены настоящий локальный API, примеры,
неизвестное слово, открытие по `#morphology`, настольная версия и ширина 390 px.
В тестовом `srcdoc` заменён `history.replaceState`, поскольку такой документ
не может менять URL; адресная навигация проверена на обычной странице приложения.

Результаты выше относятся к локальной проверке реализации. При публикации
также необходимы серверные тесты и проверка публичных API орфографии и морфологии.
